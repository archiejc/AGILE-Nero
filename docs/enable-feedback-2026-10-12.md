# 2026-10-12 使能与状态读取记录

本页保留当次测试结果。后续通过网页控制台完成的观察见 [2026-10-13 小幅移动记录](motion-test-2026-10-13.md)；该结果不改变本页 USB 配置尝试未获确认的结论。

用户明确授权使能电机、开启 CAN 推送并验证状态读取，同时要求不发送运动指令。

## 已准备的操作

显式命令：

```sh
.venv/bin/nero enable-feedback --enable-motors --firmware 1.11 \
  --config configs/local/robot.toml --seconds 30 \
  --output outputs/deployment/enable-feedback-2026-10-12.json
```

该命令使用独立配置传输类，默认 `read-state` / `listen` 的仅读策略保持不变。允许的帧与固定版本 SDK 的 `v111.enable()` 输出逐字节核对：

| ID | 数据 | 用途 |
| --- | --- | --- |
| `0x471` | `0802000000000000` | 七轴电机使能 |
| `0x470` | `0000000000000000` | 正常单臂配置 |
| `0x151` | `01ff320000000100` | CAN 控制与 CAN 推送，MOVE 字段 `0xFF` |
| `0x4AF` | `01` | 固件查询 |

允许发送的报文仅限以上精确组合。关节目标、末端目标、速度目标、轨迹、MIT 等报文及不同模式配置均被拒绝。使能重试最长 8 秒，只有七个驱动的最新使能反馈均为 true 后，才进入连续读取验收。

## 实际结果：使能未获确认

USB 写入出现 `USBTimeoutError`。最近一次尝试中，第一条 `0x471` 报文的 USB 写入完成，第二条 `0x470` 写入超时；未获得 CAN 发送 echo，也未收到电机使能反馈。USB 写入完成并不证明控制器收到或执行。

最终七个电机的状态均为 `null`（未知），不能声称使能成功或电机仍禁用。运动目标发送数为 0。详细发送尝试、USB 写入完成标记和失败阶段保存在本机 `outputs/deployment/enable-feedback-2026-10-12.json`。

21 项测试通过，包括默认诊断限制、配置报文与官方 SDK 一致性、运动目标拦截，以及状态完整性与新鲜度检查。

用户随后询问无线连接方法，已停止 USB 使能重试，并核对 Wi-Fi / 以太网手册。下一步优先通过网络控制台读取实际电机状态。网络接入说明见 `docs/network.md`。
