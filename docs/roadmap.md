# 双线并行路线图

内容线与机器人线通过版本化 DrawingTask / Toolpath 汇合。关口和详细验收定义见 [双线契约](architecture/track-contracts.md)，合成基准见 [共用样例](../examples/acceptance/README.md)。机器人线的离线设计从已知几何开始，不等待识别模型成熟。

## 内容线：文件到可检查笔画

| 阶段 | 输入 → 交付 | 目录 | 验收 |
| --- | --- | --- | --- |
| C0 已有基线 | 手工任务 JSON → Toolpath / SVG / 报告 | contracts、planning、workflow、api、artifacts | 已有离线能力；共用样例的 55 点、长度、抬落笔与指纹检查 |
| C1 向量输入 | 小型二维 CAD / SVG → 候选几何 → DrawingTask | ingestion、cad、geometry | 明确格式/实体范围；单位未知有诊断；端点、方向和曲线偏差正确；无静默丢线 |
| C1 图片输入 | 固定图片/人工参考 → 候选线条与来源 | vision、geometry | 可检查断线、重复、交叉点与尺度；置信度不足进入人工校正；与参考比较后决定模型训练 |
| C2 内容确认与优化 | 确认笔画 → 平面路径 | geometry、planning | 工具检查通过；优化前后形状在预设误差内，空行程/抬笔变化可解释 |

## 机器人线：已知路径到可验证程序

| 阶段 | 输入 → 交付 | 目录 | 验收 |
| --- | --- | --- | --- |
| R1 共享基础 | 厂商资料 + 工具/画板定义 → 模型 manifest、synthetic 标定与能力表 | assets/robots/nero、calibration、robot/profiles | 来源与版本、单位、坐标变换、关节顺序和已知能力明确；合成数据不冒充实测 |
| R2 后端选择 | 原生文件样例 / SDK 文档 / ROS 接口 → 一条优先路线及差距表 | robot/backends | 比较批量轨迹、插值、完成反馈、停止与单次执行语义；不默认 SDK 逐点发送可连续绘画 |
| R2 离线程序准备 | 共用 Toolpath + 配置 → MotionPlan → ExecutionPlan | planning/motion、robot/backends、contracts | 编译不访问设备；覆盖接近/绘制/抬笔/撤离；不支持能力明确拒绝；精确程序绑定全部来源版本 |
| R3 仿真与后端校验 | 程序 + 场景 → 带 scope 的验证报告 | simulation、后端校验器 | 限位、可达性、碰撞等预选检查通过；未知控制器语义标记 unsupported；nominal_preview 不自动授权 |

优先选择一条执行路线后再实现完整适配。controller_file、pyagxarm、ros2 三个目录先保存各自的输入输出与验收目标；本轮没有导入真实程序、安装 ROS 或调用机械臂。

## 汇合与后续阶段

| 关口 | 目标 | 完成条件 |
| --- | --- | --- |
| J1 离线汇合 | 一份内容输入可追溯到具体程序与报告 | 相同任务、几何、模型、标定、能力和后端版本；错误/取消/重复提交有可解释行为；实体执行保持不可用 |
| H1 单独授权的实机验收 | 两直线 + 圆弧 + 抬笔形成测量线稿 | 先确定工具、画板、速度条件及笔尖误差、停顿、抬笔间隙、停止响应阈值；验收适配与确认同一程序后才执行 |
| 后续上传与 Agent | 将稳定工具包装成任务 API 和工作流 | 持久化任务状态与产物版本；纯计算受控重试；部分物理执行后进入显式恢复 |

## 紧接着可以做的两个离线任务

1. 内容线：选定首轮二维向量输入范围，导入同一验收图形并与解析几何比较。
2. 机器人线：固定 NERO 模型来源，建立 synthetic 坐标变换与能力清单，取得原生轨迹文件样例后评估后端路线。

这两项可分别推进。运行产物放 outputs；稳定样例放 examples；模块状态写回各自 README。硬件历史观察是设备侧资料，不作为本轮执行授权或连续绘画已验收的证据。
