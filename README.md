# AGILE-Nero

**基于单臂机械臂的彩画线稿绘制研究 · Robotic Line Drawing for Architectural Polychrome Painting**

本项目探索如何将彩画图像转化为可由机械臂执行的绘画笔画，并结合视觉识别、几何规划、虚拟仿真与 agentic workflow，建立可复现的绘画实验流程。

第一阶段聚焦**平面载体上的线稿绘制**：从简单几何图形和经过整理的彩画线稿入手，逐步实现图像处理、笔画提取、路径规划、仿真验证和实机执行。后续再研究复杂彩画识别、小模型微调、视觉反馈与上色。

> 当前状态：Mac 开发环境已部署，型号已确认是 AgileX NERO。提供环境检查、USB-CAN 枚举、CAN 数据接收和固件 / 状态读取工具，以及独立的离线绘画几何流程。实机通信验收进度见 `docs/deployment-2026-10-12.md`；硬件标定、运动执行和实验结果将在后续阶段建立。

## 离线最小实现

现已提供独立的二维笔画规划、抬落笔路径、几何检查及 JSON / SVG 预览，核心只依赖 Python 3.12 标准库：

```sh
PYTHONPATH=src python3.12 -S -m agile_nero.drawing \
  --input examples/drawing/two-strokes.json \
  --output-dir outputs/offline-demo
PYTHONPATH=src python3.12 -S -m unittest discover -s tests -p test_drawing.py -v
```

`--output-dir` 使用新目录；省略时只输出报告。安装项目后可用 `nero-dry-run`。流程只到几何预演，报告固定标记硬件适配及实际执行不可用。MuJoCo、机械臂 SDK、Codex SDK / LangGraph 的模块边界和验证范围见 [离线实现说明](docs/offline-drawing.md)。

## 开发环境

```sh
./setup.command
source .venv/bin/activate
nero doctor
nero devices
nero listen --seconds 5
nero read-state --seconds 5
```

环境包含官方 pyAgxArm SDK、candleLight USB-CAN 接入、图像与几何处理、MuJoCo、PyTorch/MPS 和 LangGraph。依赖由 `uv.lock` 锁定。安装与诊断细节见 [环境说明](docs/environment.md)。当前设备工具用于诊断，传输层只允许固件信息查询。

## 研究目标

- 建立“彩画图像 → 可编辑笔画 → 机械臂轨迹 → 实际线稿”的实验链路。
- 以 Mac Studio 为主要开发平台，优先验证不依赖 NVIDIA GPU 的基础流程。
- 比较传统图像处理与轻量视觉模型在彩画线稿提取中的表现。
- 研究笔画顺序、抬笔策略、曲线平滑和运动约束对绘制精度及效率的影响。
- 探索 agent 对工具调用、任务分解、异常处理和实验记录的作用。

## 第一阶段：线稿绘制

### 输入与输出

**输入：** 简单几何图形、矢量线稿，或需要清理的彩画局部图像。

**中间产物：** 有序二维笔画、坐标变换、带抬笔与落笔事件的末端路径、经过运动约束检查的轨迹。

**输出：** 实际绘制的线稿、轨迹预览、运行日志和实验评估记录。

首轮采用固定笔具和固定绘画平面，控制实验变量；复杂曲面、颜料、换笔和主动力控留待后续阶段。

### 处理流程

1. **图像预处理：** 裁切、透视校正、去噪和尺度设置，保留原始图像以便比较。
2. **线稿与笔画提取：** 先建立传统图像处理基线；区分边缘轮廓与实际需要绘制的笔画中心线，处理分叉、闭合曲线和重复线。
3. **矢量化与笔画规划：** 曲线简化、平滑、采样和笔画排序，减少空行程和不必要的抬笔。
4. **坐标标定：** 将图像坐标转换为绘画平面坐标，再转换为机器人基坐标；明确单位、原点、轴方向和 TCP。
5. **轨迹生成：** 设置末端姿态、抬笔高度、速度和加速度；检查关节限位、可达性、奇异位形及碰撞。
6. **仿真与预览：** 检查笔画方向、落笔位置和轨迹连续性；仿真通过后安排低速实机验证。
7. **绘制与评估：** 从离纸空运行、单线和简单曲线开始，逐步绘制彩画局部线稿，记录误差与异常。

连续绘画需要独立的轨迹执行模块。执行机制应依据设备文档与实验确定，不能预设逐段调用点到点运动接口就能得到流畅笔画。

## 候选软件架构

以下为待验证的模块分工，并非已安装或已锁定的依赖。

| 模块 | 候选方案 | 职责 |
| --- | --- | --- |
| 图像处理 | Python、OpenCV、NumPy | 预处理、线条提取和传统方法基线 |
| 轻量模型 | 支持 Apple Silicon 的训练或推理工具 | 彩画结构识别、线稿提取及后续微调实验 |
| 几何规划 | 独立 Python 模块 | 矢量化、笔画排序、坐标变换和路径采样 |
| 运动规划 | 逆运动学与轨迹参数化工具，具体选型待定 | 将绘画路径转换为满足机器人约束的轨迹 |
| 基础仿真 | MuJoCo | 验证几何、可达性与运动行为；绘画接触模型需另行验证 |

## Agentic workflow

计划采用一个主 agent 编排受约束的工具流程。Agent 负责理解任务、选择处理步骤、读取验证结果和提出修改方案；几何计算、运动约束检查和轨迹执行由明确的程序模块完成。

| 层级 | 计划职责 | 关键边界 |
| --- | --- | --- |
| 任务编排 | 组织识别、规划、仿真、评估与重试 | 保存步骤状态与工具结果，限制重试次数 |
| 视觉与几何工具 | 从图像产生可审查的笔画和路径 | 输出结构化数据，不直接控制机械臂 |
| 验证与执行工具 | 校验标定、约束和轨迹，执行已确认任务 | 执行确定的轨迹版本；修改后重新验证 |
| 操作者 | 检查工作区、固定载体、确认落笔与启动 | 保留急停和停止执行的能力 |

计划流程包含：任务建立、线稿处理、笔画规划、轨迹生成、仿真验证、操作者确认、实机执行和结果评估。验证失败时返回对应步骤，超过重试预算后停止并保留诊断信息。

LangGraph 与 Codex SDK 都属于此前讨论中的候选方向，尚未确定最终框架。第一版先明确工具接口与流程状态，再选择编排实现。Agent 不承担高频实时伺服控制。

## 小模型与微调计划

“识别彩画”和“规划绘画路径”先拆分为可独立评估的任务：

- **识别与提取：** 检测彩画局部、区分纹样结构、提取适合绘制的线条。
- **笔画组织：** 根据结构信息辅助笔画分组和顺序选择。
- **运动生成：** 保留显式的标定、逆运动学和运动约束程序。

先用传统方法与现成模型建立基线，再决定是否需要微调。微调前需明确训练标签、数据来源和使用权，并按纹样或来源划分数据，避免同一图像的近似变体同时进入训练集与测试集。

## 实施路线

- [ ] M0：确认机械臂型号、固件、SDK、通信设备和末端方案。
- [ ] M1：完成状态读取、基础运动和绘画平面 / TCP 标定。
- [ ] M2：从手工定义的直线、圆和简单矢量图生成绘画路径。
- [ ] M3：建立仿真预览与约束检查，完成简单图形的实机绘制。
- [ ] M4：建立图像到笔画的基线，完成一个彩画局部线稿实验。
- [ ] M5：加入结果配准、误差分析和实验记录。
- [ ] M6：集成 agent 编排，比较固定流程与 agent 辅助流程。
- [ ] M7：根据基线误差与数据条件开展轻量模型微调。

## 实验评价与复现

| 方面 | 拟记录指标 |
| --- | --- |
| 线稿提取 | 人工参考线条的精确率 / 召回率、断裂与重复笔画数量 |
| 绘制精度 | 配准后的线条偏差，以毫米计；同时记录标定误差 |
| 路径效率 | 落笔长度、空行程长度、抬笔次数与总绘制时间 |
| 执行稳定性 | 轨迹跟踪误差、失败次数、通信异常和停止事件 |
| Agent 表现 | 任务完成率、工具调用次数、重试次数、人工介入次数与成本 |
| 模型效果 | 基线与微调模型的质量、推理延迟和资源使用 |

每次实验计划保存输入与授权信息、代码提交号、模型和配置版本、标定参数、笔画 / 轨迹文件、验证报告、执行日志及结果照片。阈值在标定与基线实验后制定。

## 仓库组织

当前已有 `pyproject.toml`、`uv.lock`、`src/agile_nero/`、`configs/`、`tests/`、`docs/` 和部署脚本。离线绘画模块位于 `src/agile_nero/drawing/`，后续模块继续在同一 Python 包内按职责扩展：

| 计划目录 | 内容 |
| --- | --- |
| `docs/` | 设备记录、架构决策、标定说明与实验协议 |
| `configs/` | 非敏感的设备、仿真和任务配置 |
| `src/agile_nero/drawing/` | 已实现的笔画数据、平面路径、几何校验、预演和工具入口 |
| `src/agile_nero/vision/` | 后续图像预处理与线稿提取 |
| `src/agile_nero/planning/` | 后续标定、运动规划与时间参数化 |
| `src/agile_nero/simulation/` | 后续 MuJoCo 模型与验证适配 |
| `src/agile_nero/robot/` | 后续 SDK 与轨迹执行适配 |
| `src/agile_nero/workflow/` | 后续框架编排、持久化和重试 |
| `examples/` | 获授权的小型示例与演示任务 |
| `tests/` | 坐标变换、轨迹约束等关键模块的测试 |

原始图像、权重和大量实验输出默认不提交 Git；后续按规模与授权条件决定使用 Git LFS 或外部存储。软件环境的安装与运行说明见 `docs/environment.md`。
